# 展示站计划

> 状态：第一版完成并已推送（10-28）。每完成一步，在第 6 节打勾并记一行。

## 1. 目的

把"让代码 Agent 检查自己的修复"这个研究（见根目录 `PLAN.md`）做成一个可以本地打开、给别人演示的网站。

- **3 分钟看懂**：问题、方法、结论。
- **能下钻**：每个结论都能点到具体题目、补丁、Agent 轨迹，证据可查。
- **数据来自真实结果**：数字由后端读取 `runs/` 计算，不手抄。

## 2. 范围

| 做 | 不做 |
|---|---|
| 只读展示已有的 `runs/` 结果 | 在网页上发起新的 Agent 运行 |
| 本地运行（`localhost`） | 公网部署、登录 |
| 中文界面 | 多语言 |

## 3. 技术选择

| 部分 | 选择 | 理由 |
|---|---|---|
| 后端 | FastAPI：`server.py`（接口）+ `data.py`（读数据、算指标） | 和仓库一样是 Python；计算与接口分开，便于测试 |
| 前端 | 原生 HTML / CSS / JS，无构建 | 仓库崇尚极简；不引入 node 工具链，`git clone` 后即可运行 |
| 文字内容 | `showcase/content.yaml` | 叙述文字和代码分离，改文案不用动代码 |
| 风格 | Claude 风格 | 见第 4 节 |

## 4. 风格（Claude 风格）

- **颜色**：象牙白底 `#FAF9F5`，卡片 `#F0EEE6`，正文近黑 `#141413`，次要文字 `#73726C`，强调色陶土橙 `#D97757`。
- **字体**：标题用衬线体，正文用无衬线，代码用等宽。
- **气质**：留白多、圆角柔和、线条细、少装饰；图表只用几种颜色，"通过/失败"用绿/橙。
- **文字**：短句，先给结论再给数字。
- **标志性元素**：概览页的"条形码"。每格一道题，每行一次运行，同一列是同一道题；悬停时整列高亮。一眼能看出各配置的差距大多来自随机翻转。
- **深色模式**：跟随系统（`prefers-color-scheme`），用 Claude 深色底 `#262624`。

## 5. 页面与接口

| 页面 | 内容 | 接口 |
|---|---|---|
| 概览 | 一句话结论、条形码、结果总表、7 个发现（每条链到证据） | `GET /api/overview` |
| 实验 | 50 题 × 配置的结果矩阵，可筛选：结果不一致 / 有失败归因 / 一直没解出 | `GET /api/runs` |
| 题目 | issue、各配置的补丁与测试结果、审查者意见、失败归因 | `GET /api/instances/{id}` |
| 轨迹 | Agent 每一步的说明 / 命令 / 输出（输出折叠）；B2 可切到审查者的轨迹 | `GET /api/trajectories/{run}/{id}` |
| 验证者 | pointwise 的 AUROC 陷阱、各选择方法对比、listwise 的选择理由 | `GET /api/verifier` |

数据来源：

- `runs/<run>/*/*.traj.json`：步数、token、退出状态、审查记录、轨迹
- `runs/<run>/preds.json`、`runs/eval/*.json`：补丁、是否通过
- `runs/eval/logs/run_evaluation/<run>/.../report.json`：隐藏测试明细
- `runs/verifier/*.jsonl`：补丁数据集、pointwise 分数、listwise 选择

## 7. 文件

```
showcase/
  server.py      # FastAPI：5 个只读接口 + 托管 web/
  data.py        # 读 runs/、算所有指标（与 scripts/eval_verifiers.py 的口径一致）
  content.yaml   # 所有叙述文字：标题、结论、配置名、7 个发现、失败归因
  web/           # index.html / style.css / app.js，无构建
tests/showcase/  # 用合成的小 runs/ 测加载、反事实合并、选择与 AUROC 计算
```

## 8. 运行

```bash
uv pip install -p .venv -e '.[showcase]'
.venv/bin/python -m showcase.server        # 打开 http://localhost:8000
```
